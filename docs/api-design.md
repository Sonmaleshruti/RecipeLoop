# RecipeLoop — API Design

## 1. Overview

RecipeLoop uses RESTful APIs to connect the frontend, developed using HTML, CSS, and JavaScript, with the backend developed using Java and Spring Boot. The APIs exchange data in JSON format and use HTTP methods to perform operations on recipes, ingredients, weekly meal plans, and shopping lists.

**Base URL:** `http://localhost:8080/api`

## 2. API Endpoints

### 2.1 Recipe Management

| Method | Endpoint | Description |
|---|---|---|
| GET | `/recipes` | Retrieve all recipes |
| GET | `/recipes/{id}` | Retrieve a recipe by ID |
| POST | `/recipes` | Create a new recipe |
| PUT | `/recipes/{id}` | Update an existing recipe |
| DELETE | `/recipes/{id}` | Delete a recipe |
| GET | `/recipes/search?keyword={keyword}` | Search recipes by name or description |

### 2.2 Ingredient Management

| Method | Endpoint | Description |
|---|---|---|
| GET | `/recipes/{id}/ingredients` | Retrieve ingredients for a recipe |
| POST | `/recipes/{id}/ingredients` | Add an ingredient to a recipe |
| PUT | `/recipes/{id}/ingredients/{ingredientId}` | Update a recipe ingredient |
| DELETE | `/recipes/{id}/ingredients/{ingredientId}` | Remove an ingredient from a recipe |

Each recipe ingredient contains an ingredient name, quantity, and unit of measurement.

### 2.3 Weekly Meal Planning

| Method | Endpoint | Description |
|---|---|---|
| GET | `/meal-plans` | Retrieve available weekly meal plans |
| GET | `/meal-plans/{id}` | Retrieve a weekly meal plan |
| POST | `/meal-plans` | Create a weekly meal plan |
| POST | `/meal-plans/{id}/meals` | Add a recipe to a day and meal slot |
| DELETE | `/meal-plans/{id}/meals/{mealId}` | Remove a planned meal |

A planned meal contains the recipe ID, date, and meal slot, such as breakfast, lunch, or dinner.

### 2.4 Shopping List Management

| Method | Endpoint | Description |
|---|---|---|
| POST | `/meal-plans/{id}/shopping-list/generate` | Generate or refresh the shopping list |
| GET | `/meal-plans/{id}/shopping-list` | Retrieve the shopping list |
| PATCH | `/shopping-list-items/{id}/purchased` | Mark an item as purchased or not purchased |
| DELETE | `/shopping-list-items/{id}` | Remove an item from the shopping list |

The shopping list is generated by combining ingredients from the recipes selected in the weekly meal plan. Compatible units are consolidated, while incompatible units remain separate. Regenerating the list must not create duplicate entries for the same ingredient and unit.

### 2.5 Intelligent Recipe Recommendations

| Method | Endpoint | Description |
|---|---|---|
| GET | `/recommendations?recipeId={id}` | Recommend recipes related to a selected recipe |
| GET | `/recommendations?keyword={keyword}` | Recommend recipes related to a search keyword |

The recommendation component uses TF-IDF vectorization and cosine similarity to compare recipe names, descriptions, and available ingredient text. It returns recipes with similar content. The system does not claim personalized recommendations based on user history.

## 3. Sample Request and Response

### Create a Recipe

**Request**

`POST /api/recipes`

```json
{
  "name": "Vegetable Sandwich",
  "description": "A simple sandwich with fresh vegetables.",
  "preparationTime": 15,
  "instructions": "Prepare the vegetables, assemble the sandwich, and serve.",
  "ingredients": [
    {
      "name": "Bread",
      "quantity": 4,
      "unit": "slices"
    },
    {
      "name": "Tomato",
      "quantity": 1,
      "unit": "piece"
    }
  ]
}
```

**Successful response:** HTTP `201 Created`, containing the newly created recipe and its assigned ID.

## 4. HTTP Status Codes

| Status Code | Meaning |
|---|---|
| 200 OK | Request completed successfully |
| 201 Created | Resource created successfully |
| 204 No Content | Resource deleted successfully |
| 400 Bad Request | Invalid request data |
| 404 Not Found | Requested resource does not exist |
| 500 Internal Server Error | Unexpected server-side error |

## 5. Validation and Error Handling

1. Recipe names and required fields must not be empty.
2. Ingredient quantities must be positive numbers.
3. Preparation time must be zero or a positive number.
4. A recipe, meal plan, or shopping-list item must exist before it can be updated or deleted.
5. Invalid requests must return an appropriate HTTP status code and a clear error message.
6. Deleting a recipe must be handled safely if it is referenced by an existing meal plan.

## 6. API Implementation

The APIs will be implemented using Spring Boot REST controllers. Business logic will be handled by service classes, and data persistence will use Spring Data JPA and Hibernate with MySQL.

The frontend will call these APIs using JavaScript `fetch()` requests. The backend will validate requests, execute the required operations, and return JSON responses.
